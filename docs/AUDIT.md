### Сильные стороны (беречь при рефакторинге)
- **Модель бесшовности:** глобальное время `T`, непрерывное `state` между сценами, один микс на ролик,
  склейка `-c copy`. Проверено на реальном 7-минутном ролике.
- **Кэши по содержимому:** TTS по хэшу текста+настроек, рендер по хэшу сцены. Правка одной сцены = перерендер одной сцены.
- **Состояние в файлах** (`status`), а не в памяти сессии. Новая сессия сразу знает, где остановились.
- **Железные правила** (речь не режем и не ускоряем, сначала stills, без TTS не работаем) зашиты в код и документы.
- **Защита денег:** ElevenLabs — оценка символов и `--yes`, `rate` числом, кэш от повторной оплаты.
- **Синхронизация по словам** (`at: "66"`) от таймкодов ElevenLabs/edge — сильная фича для «живой» анимации.

### 3.2 Качество картинки и проверка качества
- 🔴 **Вертикаль у `lab_*` не свёрстана** (известно с интеграции, STYLE §12), а регресс собирается именно в вертикали:
  на листе `final_frames.png` заголовок главы обрезан справа, `lab_versus` сжат в левый верхний угол.
  **QA при этом — 15/15 ✅.** То есть QA проверяет технику (кадры, звук, тайминг), но не вёрстку.
  Для TikTok/Reels/Shorts (9:16) это блокер. *Закрыто: проверка — P1.10, вёрстка 9:16 и 4:5 и ❌ в QA — ROADMAP B2.*
- 🟠 Нет проверки «контент в безопасной зоне»: ни поля кадра, ни зоны интерфейса платформ (кнопки TikTok справа и снизу).
- 🟠 Темп голоса не калибруется: `wpm` берётся из `lang.py` (en 155), реальный ElevenLabs — 185. Бюджеты слов в `outline.md`
  дают ошибку длительности ~20 %.

### 3.3 Архитектура (мешает расти: несколько студий, брендов, платформ)
- 🟠 **Глобальное изменяемое состояние стиля:** `gfx.PAL`, `gfx.STYLE`, `gfx.STYLE_KEY`, `gfx.FONT_FAMILY` (`gfx.py:44-58`)
  меняются при каждом `prepare`; шаблоны импортируют `PAL` напрямую. Два бренда в одном процессе (галерея, пакетный
  рендер, ревью-сервер) смешают палитры. Скрытый канал и в TTS: `tts._EL_CFG` (`tts.py:146`) передаёт настройки
  бэкенду через глобальный словарь.
- 🟠 **Реестр шаблонов — один плоский словарь** (`templates.py:23`): проектные шаблоны исполняются через `exec_module`
  и регистрируются глобально; одинаковые имена у двух проектов/студий молча перетрут друг друга. Нет схемы параметров
  (только список имён) и нет признака «какие форматы кадра шаблон поддерживает».
- 🟠 **Ключ кэша рендера — ручной список файлов** (`render.py:29`). Новый модуль рисования, не внесённый в список, не
  инвалидирует кэш → устаревшие сцены после правки кода. Любой распил `lab.py` обязан это учесть.
- 🟠 **Пути жёстко на `STUDIO_ROOT/projects`** (`project.py:12,90,132`, `cli.py:57`). Одна студия = один канал.
  Канал размазан по корню: `channel/`, `briefs/`, `research/`, `scripts/` — второй канал некуда положить.
- 🟠 **Формат ролика один:** «диктор + анимация + субтитры». Нет медиа-слоя (фото, видео, логотип), нет роликов без
  голоса, нет нескольких выходов из одного проекта (16:9 + 9:16 + 1:1).
- 🟡 `cli.py` смешивает CLI и логику (`validate`, проверки стиля и голоса — 120 строк внутри CLI).
- 🟡 `lab.py` — 1 469 строк в одном файле: фон, примитивы, элементы, 8 шаблонов.
- 🟡 Два `prog` с разной семантикой: `gfx.prog(t, a, b)` (конец) и `motion.prog(t, start, dur)` (длительность). Дубли
  `clamp`/`lerp`.
- 🟡 Циклический импорт «по договорённости»: `templates.py` в конце импортирует `lab`, `lab` импортирует `templates`.
- 🟡 `project.yaml` без схемы и версии: опечатка в ключе (`subtitle:` вместо `subtitles:`) молча игнорируется.
- 🟡 Проектный шаблон `money.py` (683 строки) — фактически общий «ценник/число» для коммерческих роликов, живёт в проекте.

### 3.4 Производительность и ресурсы
- 🟠 **Камера стоит почти половину кадра** (`lab.py:99`, `render.py:190`): affine-преобразование всего RGBA-слоя 1920×1080
  каждый кадр, хотя контент занимает его малую часть. (В отчёте интеграции было «дрейф камеры почти не стоит времени» —
  на реальных сценах это не так.)
- 🟠 **Фон `lab` — треть кадра:** два поля подсветки в numpy, resize до полного кадра, сложение с зерном полного кадра.
- 🟠 **Плохая параллельность:** 24 процесса ≈ 4,6× от одного. Число процессов по умолчанию = `os.cpu_count()` (логические
  ядра) + каждый процесс держит свой ffmpeg. Длинная сцена в конце очереди рендерится одна («s14: 306 кадров за 168 с»).
- 🟠 **Диск:** `build/chapters/` дублирует `build/render/`; `build/mix/` держит 4 промежуточных WAV; очистки нет.
- 🟡 Голос и SFX собираются в RAM float32 на весь ролик (`audio.py:23-38`) — для часа ≈ 0,7 ГБ на дорожку.
- 🟡 `prepare()` (инстанцирует все шаблоны) повторяется в `status`, `assemble`, `sfx_events`.

### 3.5 Процесс и документация
- 🔴 **Нет страховочной сетки.** Единственная проверка «ничего не сломал» — регресс, который (а) не запускается на этой
  машине, (б) зависит от сети (edge) и (в) проходит при визуально сломанных кадрах. Рефакторинг без неё — лотерея.
- 🟡 Устаревшие места в документах: `START_HERE.md` («~2700 строк», «Куда дальше» по старому ROADMAP, таблица
  «не проверено» про edge/Windows), `README.md` («ru по умолчанию» при английском канале), `ARCHITECTURE.md`
  (замеры только по 30-секундному демо, «R5–R7» и т.п.).
- 🟡 Логи разбросаны: `projects/<slug>/*.log`, `build/*.log`, `logs/` — каждая сессия кладёт по-своему.
- 🟡 Старый `ROADMAP.md`: часть задач уже сделана, но не отмечена (R5a — ElevenLabs работает в бою; R7 — пилот 7 минут
  фактически пройден), часть устарела по смыслу (ориентирован на один канал и «часовой ролик» как цель).
