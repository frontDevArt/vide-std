Задачи идут по порядку ценности. У каждой: зачем, что сделать, критерий «готово» и промпт,
который можно вставить в Claude CLI как есть (или выполнить `/roadmap` — он возьмёт первую невыполненную).
Отмечайте выполненное `[x]` прямо в этом файле.

Общее правило для всех задач: после изменения кода — прогнать `python -m studio all minutka`
и `python -m studio all habit-demo`; оба QA должны остаться ✅.

## Этап A — удобство работы (1–2 сессии)

### [ ] R1. Просмотрщик сцен с комментариями (`studio review`)
**Зачем.** Сейчас правку надо описывать словами («в сцене 3 карточка слишком рано»). Идея из гайда
(стр. 22, «review rig»): смотришь клипы сцен, ставишь метку на секунде — Claude получает точный список правок.
У нас уже есть отдельный MP4 на каждую сцену и кэш, поэтому правится только помеченная сцена.
**Сделать.**
- `python -m studio review <проект>` поднимает локальный сервер на `127.0.0.1` (stdlib `http.server`, без зависимостей), сам браузер не открывает, печатает адрес.
- Страница: список глав → карточки сцен (видео `build/render/chNN/sNN.mp4`, текст строк, шаблон, длительность).
- Клик по видео = комментарий с секундой (локальной и глобальной) и координатами точки; сохраняется в `projects/<slug>/review/comments.json`.
- Кнопка «Скопировать для Claude»: все открытые комментарии одним текстом вида
  `ch01/s03 @2.40s (глоб. 11.20s), точка (0.52, 0.31): карточка появляется раньше слова`.
- Кнопка «Готово» у комментария. Ничего не удаляет и не трогает файлы, кроме `comments.json`.
- Команда `/review-fix` в `.claude/commands/`: читает открытые комментарии, правит входы, `voice` → `stills` по затронутым сценам → `render` → закрывает комментарии.
**Готово, если:** на `minutka` можно оставить 2 комментария, `/review-fix` правит только эти сцены (в логе рендера — только они).
**Промпт:**
```
Сделай задачу R1 из docs/ROADMAP.md: просмотрщик сцен с комментариями `python -m studio review`.
Только stdlib Python (http.server), один HTML-файл со встроенным JS/CSS, слушать 127.0.0.1,
не открывать браузер самому, хранить комментарии в projects/<slug>/review/comments.json.
Добавь команду .claude/commands/review-fix.md. Проверь на projects/minutka и покажи, какие сцены
перерендерились после исправления.
```

### [ ] R2. Бриф по схеме гайда: `avoid` и `done_means`
**Зачем.** В гайде (стр. 7) хороший бриф = вид + кто смотрит/где + сцены с секундами + **чего избегать** +
**что значит готово**. Последних двух у нас нет, а они превращаются в проверки.
**Сделать.** Поля в `project.yaml`:
```yaml
avoid: ["больше 6 слов на экране одновременно", "текст у краёв кадра", "факты, которых нет в брифе"]
done_means: ["все сцены по порядку", "каждое слово читается на телефоне", "финальный титр держится ≥ 1.5 c"]
```
`validate` проверяет то, что проверяемо автоматически (слова на экране в параметрах шаблонов, длина
`hold` у финала), остальное `qa` выводит в отчёт как чек-лист «проверить глазами».
Обновить `docs/PHASES.md` (фаза 1) и `/new-video`.
**Готово, если:** нарушение «больше N слов» ловится `validate` с понятным сообщением.
**Промпт:** `Сделай R2 из docs/ROADMAP.md. Добавь поля avoid и done_means, автоматические проверки в validate и чек-лист в qa/report.md.`

### [ ] R3. Стили-пресеты (8 стилей гайда)
**Зачем.** На длинной дистанции однообразие убивает внимание. Гайд (стр. 24–26) даёт 8 узнаваемых стилей:
кинетическая типографика, ризограф, чертёж→реальность, мел на доске, изометрия, 8-бит, скетчноут, поп-арт комикс.
**Сделать.** В `gfx.PALETTES` + режимы фона в `Background`: `paper` (зерно, кремовая бумага),
`blueprint` (сетка), `chalkboard` (меловые разводы), `scanlines` (8-бит). Параметры стиля: шрифт, толщина
обводки, свечение вкл/выкл, «смещение печати» (riso — два цвета со сдвигом в 2–4 px).
**Решение пользователя (2026-10-20): стиль привязан к ролику целиком.** Задаётся один раз до старта
(фаза брифа), фиксируется в `project.yaml` (`style.preset`) и в `outline.md` как сквозное решение;
внутри ролика не меняется — переопределения на главу **нет**.
**Свой стиль пользователя.** Перед началом ролика пользователь может дать описание стиля + скриншот(ы)
референса. Тогда: скриншот кладётся в `projects/<slug>/style/ref*.png`, описание — в `style/brief.md`;
Claude разбирает референс (цвета фона/текста/акцентов, шрифт, обводки, свечение, фактура фона) и
записывает это как `style.custom` в `project.yaml` (те же параметры, что у пресетов) → `stills` →
пользователь подтверждает кадры → стиль закреплён, дальше сценарий и рендер. Без референса —
выбор одного из пресетов. `/new-video` и `docs/PHASES.md` (фаза 1) спрашивают про стиль первым делом.
**Готово, если:** `habit-demo` собирается в 4 разных стилях, листы `stills` явно различаются; плюс один
прогон со своим стилем по скриншоту — `stills` визуально похожи на референс.
**Промпт:** `Сделай R3 из docs/ROADMAP.md: пресеты стилей + свой стиль по описанию и скриншоту. Начни с riso, blueprint, chalkboard и paper-sketch, покажи листы stills для habit-demo в каждом.`

### [ ] R4. Экспорт с прозрачным фоном
**Зачем.** Гайд накладывает графику на своё видео через зелёный фон и хромакей (стр. 11). Мы можем отдать
альфа-канал напрямую — чище, без зелёной каймы.
**Сделать.** `render.alpha: true` → фон не рисуется, кадры RGBA → `ProRes 4444` (`.mov`) или `VP9 + alpha` (`.webm`).
Субтитры — флагом (обычно их делают в монтажке из `.srt`).
**Готово, если:** `.mov` открывается в монтажке поверх другого видео без фона.

### [ ] R5a. Бэкенд ElevenLabs + бесшовная смена голоса
*Прогресс (2026-10-21, channel-kit):* бэкенд `elevenlabs` написан (`/with-timestamps`, ключ из `.env`, `voice --yes`), не проверен вызовом — нет ключа. Проверка Dmitry→Svetlana не делалась.
**Зачем.** Сейчас ролики озвучиваются бесплатно (`edge`). По решению пользователя их нужно переозвучить
голосом ElevenLabs — **без правки сценария и с идеальной синхронизацией**: длительность речи, кадры,
границы предложений/битов и субтитры должны совпасть с новым голосом. **Не включать без явного
решения пользователя** (платно).
**Почему это реально.** Тайминг уже строится по реальному WAV, а не по тексту (`studio/timing.py`):
строка синтезируется целиком → длительность измеряется → биты `|` притягиваются к настоящим паузам →
всё квантуется в кадры. Смена `tts.backend`/`tts.voice` меняет `source_hash` → таймлайн пересчитывается,
перерендериваются только сцены с изменившейся длительностью.
**Сделать.**
- `_elevenlabs` в `studio/tts.py`: stdlib `urllib`, `POST /v1/text-to-speech/{voice_id}` с
  `output_format` PCM/MP3, `model_id` из `tts.model` (по умолчанию multilingual-модель с русским).
  Ключ — **только** из переменной окружения `ELEVENLABS_API_KEY` (не в yaml, не в git, не в логах).
- Темп: наш `rate` (проценты) → `voice_settings.speed` = `rate/100` с ограничением диапазона, который
  принимает API (≈0.7–1.2; проверить по актуальной документации через context7/веб).
- Ключ кэша TTS включает `tts.model` и `voice_settings` (stability, similarity), чтобы смена настроек
  вызывала пересинтез; кэш защищает от повторной оплаты тех же строк.
- `probe()` для ElevenLabs — короткая фраза; 401/403/429 — понятная ошибка, **без ретраев** на 403.
- Перед синтезом: оценка расхода (сумма символов всех `lines`) и вывод пользователю → подтверждение.
- Смена голоса одной правкой: `tts.backend: elevenlabs`, `tts.voice: <voice_id>`. Для длинных роликов —
  заново подобрать и зафиксировать `tts.rate` по главе 1 (у другого голоса другой естественный темп).
- Если новый голос не влезает в `target_duration` в пределах `rate_range` — остановиться и предложить
  сократить текст (речь не резать и не ускорять — железное правило).
- `docs/TTS.md`: строка в таблице бэкендов + раздел «Смена голоса на готовом ролике».
**Проверка без ключа (можно сделать заранее, бесплатно).** Собрать `minutka` голосом `ru-RU-DmitryNeural`,
затем переключить на `ru-RU-SvetlanaNeural` и пересобрать: оба раза `qa` — все ✅, `qa/subs_check.png`
и `qa/final_frames.png` без рассинхрона; в логе рендера видно, какие сцены пересчитались.
**Готово, если:** проверка Dmitry→Svetlana проходит; с ключом `minutka` переозвучивается ElevenLabs
одной правкой `project.yaml` + `voice` → `render` → `assemble`, и `qa` — все ✅.
**Промпт:**

### [ ] R11. Оценить HyperFrames как второй движок рендера
**Зачем.** HyperFrames (HeyGen, Apache 2.0, плагин Claude Code; стр. 20–21 гайда) рендерит HTML-страницы
в MP4 и умеет вставлять своё видео/аудио. HTML/CSS/анимации — богаче визуал быстрее, чем PIL.
**Как (спайк, 1 сессия).** Не переписывать студию. Сделать один шаблон-мост `html`: сцена рендерится
HyperFrames-ом в MP4 с теми же размерами/fps, а наш пайплайн (сценарий, озвучка, тайминги, субтитры,
микс, главы, QA) остаётся. Замерить: кадры/с на 1080p, совместимость склейки `-c copy`
(может понадобиться перекодирование), детерминизм рендера.
**Готово, если:** есть таблица «PIL vs HyperFrames» с цифрами и решение, для каких сцен что использовать.
**Промпт:** `Сделай спайк R11 из docs/ROADMAP.md. Установи HyperFrames по docs/reference/claude-motion-guide.pdf (стр. 20), отрендерь одну сцену minutka через него и сравни скорость и качество с нашим рендером. Студию не ломай.`
