# План рефакторинга и оптимизации

Основа — [`AUDIT.md`](AUDIT.md) (2026-10-22). Цель: убрать найденные баги, подготовить движок к мультистудии и
мультиплатформе ([`ROADMAP.md`](ROADMAP.md)), ускорить рендер — **и при этом ничего не сломать**.
`/roadmap` берёт первую неотмеченную задачу отсюда, пока этапы 0–2 не закрыты. Отмечайте `[x]` по факту.

## Правила «ничего не сломать»
1. **Сначала сетка.** Ни одной правки движка, пока не закрыт этап 0 (до P0.5 включительно).
2. **Один пункт = одна ветка = один PR.** Перед мержем зелёные `pytest` и `python -m studio selftest`.
3. **Рефакторинг не меняет поведение.** На этапах 2 и 4 golden-файлы совпадают байт в байт. Если golden поменялся,
   это уже не рефакторинг: отдельное решение с объяснением в коммите.
4. **Баг — сначала падающий тест**, потом фикс. Golden обновляется только в той части, которую затрагивает баг.
5. **Старые входы работают.** Старые `project.yaml` и `script/*.yaml` грузятся без правок (миграция в памяти),
   старые имена шаблонов остаются алиасами, команды и флаги CLI только добавляются, а не переименовываются.
6. **Готовые ролики не трогаем.** После любой правки кода рисования кэш рендера проектов устаревает: в ключе есть
   хэш кода, так и задумано. Перерендер нужен, только когда проект правят.
7. **`fake-discounts` — живой эталон.** До начала работ сохранить его листы `stills` в `tests/reference/`.
   После каждого этапа — `stills` и сравнение глазами.
8. **Тесты не ходят в сеть и не тратят деньги.** ElevenLabs и edge в тестах не вызываются, только `fake`.

Порядок: **0 → 1 → 2 → (3 ‖ 4) → 5**. Оценка — 11–13 сессий; этапы 3 и 4 можно вести параллельно.
