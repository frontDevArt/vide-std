# Фазы производства

Каждая фаза — законченный шаг с понятным «готово, если». Состояние фаз вычисляется из файлов:
`python -m studio status <проект>` всегда скажет, что делать дальше. Одна сессия Claude может пройти
несколько фаз (короткий ролик) или одну фазу одной главы (длинный ролик).

---

## Фаза 0 — Окружение (один раз на машину)
```bash
pip install -r requirements.txt
python -m studio doctor
bash tools/setup_rhvoice.sh        # если doctor не нашёл ни одного рабочего TTS
```
**Готово, если:** `doctor` показывает хотя бы один TTS с «синтез работает».
**Если TTS нет совсем — сказать пользователю прямо и остановиться. Не делать ролик «только с субтитрами».**

## Фаза 1 — Бриф → `project.yaml`
Вход: тема от пользователя. Создать: `python -m studio new "<тема>" --format vertical [--duration 30] [--tts <голос>]`.
Ролик студии (канал, бренд) — `… --studio <id>` → `studios/<id>/projects/<slug>/`, язык и голос по умолчанию — из её `studio.yaml`.
Без `--tts` голос — из `voices:` студии для языка (ROADMAP A3), иначе первый доступный на машине: `elevenlabs` (канал, `--lang en`, ключ в `.env`) → `edge` → `rhvoice`;
выбор записывается в `project.yaml` явно (бэкенд входит в ключ кэша TTS). Нет ни одного — ⚠️ и `rhvoice`: поставить голос.
Тип ролика — `kind` (`python -m studio kinds`, ROADMAP C1; `new --kind <тип>`): `explainer` (по умолчанию), `short-hook`
(15–60 с, точная длительность, `brief.hook`), `promo` (`brief: {product, price, cta}`; фото продукта и логотип —
`media.product_card`, `media.logo_sting`), `music` (без голоса, под трек; склейки в долю — `music.sync: beat`, ROADMAP C3), `listicle` (`brief.count`, сцены `item: 1…N`),
`slideshow` (фото + подписи, без голоса, `media.image`), `tutorial` (запись экрана, `media.screen`), `clip` (кусок
подкаста/интервью, речь — звук исходника, `media.clip`), `data-story` (графики `chart` из CSV в `assets/`, ROADMAP C4). Тип задаёт голос, пределы длительности, обязательные поля `brief:` и проверки validate/QA; у типов с
файлами брифа (фото, CSV, запись экрана) в `status` есть фаза «1б Материалы»: файлы кладутся в `assets/`, а их
источник и лицензия — в `assets.yaml` (`docs/SCENE_SPEC.md`, «Фото, видео, логотип»). Без голоса (`music`, `slideshow`) —
`tts.backend: none`: сцены без `lines`, длительность — `min_duration`, правило «нет голоса — стоп» не действует.
Заполнить: `title`, `topic`, `audience` (кто зритель и что он должен вынести), `language` (ru по умолчанию;
en и др. — `--lang`), формат, точная длительность или `null`, голос (`auto` — по языку), палитра, порядок глав.
Если в запросе нет ключевого (длина/формат) — один короткий вопрос; иначе разумные значения по умолчанию:
- до 60 с → `vertical`, `target_duration` = запрошенное, одна глава;
- длиннее → `horizontal`, `target_duration: null`, главы по 3–8 минут.
Канал (`palette: lab`): `style.mood` (настроение §14 `studios/notes-from-the-mind/channel/STYLE.md`) — выбрать здесь; затем сценарий
демо в `demo/ch01.yaml` и `python -m studio demo <проект>` → MP4 пользователю, ждать утверждения до фазы 2.
Картинки (ROADMAP C5, `docs/IMAGES.md`): нужны ли сгенерированные картинки и в каких сценах — решить здесь. Да —
блок `images: {enabled: true, style: "<суффикс стиля>", budget_usd: 3}` в `project.yaml`, сцены просят их блоком
`image:` (`docs/SCENE_SPEC.md`); `status` добавит фазу «3б Картинки». Нет — блока нет, только кодовая графика.
Генерация платная: после сценария — `python -m studio images <проект>` (смета), «да» пользователя на сумму →
`--yes`; файлы и их лицензии — в `assets.yaml`.
**Готово, если:** нет `TODO` в title/topic, `chapters` перечислены.

## Фаза 2 — План → `outline.md`
Идея в одном предложении; таблица глав (что, хронометраж, бюджет слов: **`wpm` языка** — ru ~145, en ~155 слов/мин);
визуальная линия (какие шаблоны, сквозной мотив); «сквозные решения», которые нельзя менять между
сессиями (язык, голос, темп, термины, палитра).
Призывы (по умолчанию, если бриф не отключил): подписка один раз в середине (~35–50%, после первой
ценности, вплетена в речь, без смены темпа/музыки) + конкретный вопрос для комментариев ближе к концу —
место и формулировку записать в outline.md (правила — `studios/notes-from-the-mind/briefs/_TEMPLATE.md`, раздел 10).
Для длинного ролика: у каждой главы своя мини-дуга (крючок → суть → вывод → мост к следующей).
**Готово, если:** сумма бюджетов слов ≈ длительность × wpm/60, нет `TODO`.

## Фаза 3 — Сценарий главы → `script/chNN.yaml`
По одной главе за раз. Формат — `docs/SCENE_SPEC.md`, шаблоны — `python -m studio templates`.
Правила текста под озвучку:
- одна строка `lines` = одно предложение (или законченная фраза); `|` — точка синхронизации внутри;
- число битов совпадает с тем, что ждёт шаблон (карточек/пунктов/вопросов);
- текст на языке проекта, без чужого алфавита и аббревиатур (ru: «ютуб», «эс-эм-эс»; en: без кириллицы,
  аббревиатуры так, как их читать), числа — словами, если важно произношение;
- сцена 3–12 с; смена визуала минимум раз в ~6–8 с;
- акцент голоса (`voice:` у сцены или строки, ElevenLabs) — максимум 1–2 на ролик: крючок и вердикт
  (`docs/TTS.md`, «Акцент»); остальное — ровный рассказчик.
Пресет `lab` (канал): шаблон `lab_*` на сцену, элементы — по словам-триггерам `at`, разрыв ритма каждые 20–30 с,
чек-лист `studios/notes-from-the-mind/channel/STYLE.md` §13 (см. `docs/SCENE_SPEC.md`, «Шаблоны канала»).
После: `python -m studio validate <проект>`.
**Готово, если:** validate без ❌, предупреждения осознанно приняты.

## Фаза 4 — Озвучка и тайминг
`python -m studio voice <проект>` → `build/timeline.json`, `build/final/*.srt`.
Кэш TTS: уже озвученные главы не синтезируются повторно.
Проверить вывод: темп в диапазоне, длительности сцен разумные, битов столько, сколько нужно шаблонам.
Для длинного ролика после первой главы **зафиксировать `tts.rate` числом** в `project.yaml`.
Триггеры `at:` сцен `lab_*` проверяются сразу по словам озвучки: ненайденное слово или бит — ❌ с подсказкой
похожих слов и код возврата 1 (`timeline.json` записан — поправьте `at` или текст и повторите `voice`).
Замер темпа голоса пишется в `build/voice_calibration.json` (и в `voices.yaml` студии — следующий проект с тем же голосом считается по нему); расхождение с `wpm` языка > 10 % — ⚠️ с бюджетом слов
на целевую длительность (пересчитайте бюджеты в `outline.md`). `validate` и `status` дальше считают по замеру.
**Готово, если:** нет ошибки «текст не помещается»; нет ❌ по триггерам; `wpm` ~ 130–170.

## Фаза 5 — Контрольные кадры (дёшево, до рендера)
`python -m studio stills <проект> [--chapter chNN]` → `qa/stills_*.png`. **Открыть и посмотреть.**
Смотреть: наложения, обрезки по краям, читаемость, совпадает ли картинка со словами, стыки сцен
(`--times` с моментами за 0.05 с до и после границы — яркость/положение должны совпадать).
После листа `stills` печатает ❌ «контент у края» по сценам, чей контент (без фона и субтитров) заходит в поля кадра
(`qa.safe_margin` в `project.yaml`, по умолчанию 0.04 — 4 % стороны; камера не учитывается). У проекта с `platform:` поля —
не меньше безопасной зоны площадки, плюс её интерфейс (колонка кнопок справа у TikTok/Shorts): ❌ «под интерфейсом
площадки». Зоны — `python -m studio platforms`. Шаблоны верстаются в той же зоне (ROADMAP B2), поэтому ❌ — дефект:
поправить сцену (короче текст, меньше пунктов) или шаблон.
Правки → снова stills. **Готово, если:** на листе нет дефектов.

## Фаза 6 — Рендер
`python -m studio render <проект> [--chapter chNN]` — **запускать в фоне**, долго. Вывод студия сама пишет в
`projects/<slug>/logs/render-<время>.log` (прогресс — по нему).
Кэш по сценам: повторный запуск рендерит только изменённые/недоделанные сцены.
Черновик для ревью/быстрой итерации — `render --draft`: половина разрешения, x264 `ultrafast`, свой кэш
`build/render-draft/` (чистовой не трогает), `assemble --draft` → `build/final/<slug>.draft.mp4`. Пользователю как
финал не отдавать; `qa` проверяет только чистовой финал.
**Готово, если:** `status` → «N/N сцен актуальны».

## Фаза 7 — Сборка
`python -m studio assemble <проект>` → `build/final/<slug>.mp4` (видео склеивается из сцен без перекодирования,
файлы глав `build/chapters/chNN.mp4` — только с `--chapters`;
звук — общий микс на весь ролик: голос по таймлайну + музыка с приглушением + нормализация LUFS).

## Фаза 8 — QA и сдача
`python -m studio qa <проект>` → `qa/report.md`, `qa/subs_check.png`, `qa/final_frames.png`.
**Открыть оба PNG.** Все пункты ✅ — только тогда отдавать файл пользователю.
Тип ролика (ROADMAP C1) — строки «Тип <kind>: длительность …» (пределы типа), у типов без голоса «Тип <kind>: без
голоса» и «Музыка звучит» (средний уровень итога > −35 dB), у `clip` — «Звук исходника звучит» — ❌ при нарушении.
«Ассеты: источник и лицензия» — у каждого фото, видео и звука из сцен есть запись в `assets.yaml` с `source` и `license`
(иначе ❌; без медиа — ⏭️).
⏭️ — проверка неприменима и на итог не влияет: без речи (`lines` пусты) — голос, темп, обрезка слов, субтитры;
`subtitles.enabled: false` — субтитры. Субтитров нет — нет и `qa/subs_check.png` (смотреть только `final_frames.png`).
«Контент в безопасной зоне» (то же, что после `stills`) — ❌ при нарушении (с ROADMAP B2; до него был ⚠️).
`platform:` в `project.yaml` (ROADMAP B1) — ещё строки «Площадка <id>: …»: кадр, FPS, длительность в пределах
площадки, кодеки — ❌ при нарушении; громкость (громче нормы площадки — приглушит), битрейт (где площадка требует
минимум), выключенные субтитры при вшитых у площадки — ⚠️. Профили — `python -m studio platforms [<id>]`.
`deliverables:` (ROADMAP B3) — `qa` проверяет каждый выход: `qa/<выход>/report.md` и листы, финалы —
`output/<slug>/<выход>.mp4`; один выход — `--out <выход>`.
Нарезка (ROADMAP B4): после длинного ролика — `python -m studio cutdown <проект> --to youtube-shorts` (или `--list`,
посмотреть отрезки), прочитать `script/*.yaml` нарезок, при нужде дописать крючок и CTA, затем каждую — по фазам 3–8
(`docs/ARCHITECTURE.md`, «Нарезка»). Правила канала про Shorts (длительность, «один факт») — в его `channel/`.
Пакет к выходу (ROADMAP B5): `python -m studio package <проект>` (последний шаг `all`) — в `output/<slug>/` рядом
с MP4: `<выход>.cover.jpg` (открыть глазами), `<выход>.description.md` (название, описание — блоком для копирования,
главы YouTube, источники, хэштеги), `<выход>.checklist.md` (что проверить перед публикацией, отметка ИИ-контента).
Тексты — `package:` в `project.yaml` (`docs/ARCHITECTURE.md`, «Пакет к выходу»). ❌ пакета — нет MP4, у канала нет
источников, название/описание длиннее предела площадки, обложка тяжелее предела.
Сдача: MP4 + `.srt` + одна строка о результате (длительность, голос, что проверено).
