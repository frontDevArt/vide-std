# Замеры скорости и диска

Точка отсчёта для этапов 3–4 [`REFACTOR_PLAN.md`](../REFACTOR_PLAN.md). Каждый новый замер — новым разделом сверху,
той же командой, на той же машине; в начале раздела — что поменялось в коде.

Как снимать (офлайн, без синтеза и денег):
```
python tools/bench.py templates --format horizontal      # кадр/с по шаблонам, 1 процесс
python tools/bench.py templates --format vertical
python tools/bench.py project projects/fake-discounts --workers 24   # полный рендер копии проекта
python -m studio selftest
```
`project` рендерит копию во временной папке с голосом из кэша `build/tts` — сам проект не трогается.
Во время замера ничего тяжёлого параллельно не запускать. Разброс между прогонами — около ±5 %; первый прогон
после старта машины бывает медленнее (холодный диск), его не брать.

## 2026-10-22 — P3.1 камера только по плиткам с контентом

Что поменялось: `composite_camera` (`studio/packs/lab/background.py`) — affine только по полосам/плиткам 32 px, чей
прообраз задевает непустой контент; golden байт в байт. Машина та же, код — `master` после этапа 2 (`0f04d9f`) + P3.1.

| Полный рендер `fake-discounts`, 24 процесса | 225 с | **216 с (−4 %)**, 58,2 кадр/с |
| `selftest` | 73 с | 81 с (render 43 с — без изменений; разброс qa) |

Кадр/с по шаблонам после правки, horizontal: `lab_chapter` 16,0 · `lab_hero_stack` 17,4 · `lab_crowd` 16,2 ·
`lab_flow` 23,6 · `lab_diagram` 23,2 · `lab_versus` 18,2 · `lab_full_number` 15,9 · `lab_verdict` 16,7; базовые шаблоны
не менялись (камеры у них нет). Vertical: 16,0 · 19,1 · 17,2 · 24,0 · 22,8 · 19,4 · 16,4 · 16,3.

**Почему полный рендер почти не ускорился.** Кадр в одном процессе стал на 36 % дешевле, а 24 процесса — лишь на 4 %:
при 24 процессах на 16 физических ядрах (8 из них E-ядра) и своём ffmpeg у каждого упор — в общую пропускную
способность CPU/памяти и в «хвост» длинных сцен, а не в стоимость кадра. Это задача P3.3 (число процессов, нарезка сцен);
выигрыш P3.1 проявится там, где процессов не больше физических ядер, и складывается с P3.2.

### Что видно (к этапу 3)
- В `lab_*` камера — **50–57 %** кадра (аудит давал 46 % на `fake-discounts`, там больше рисования шаблона), фон —
  29–34 %. Само рисование шаблона — 3–17 %. Цели P3.1 (−35 % кадра) и P3.2 (−50 % фона) бьют ровно в эти фазы.
- Без камеры кадр в 2,5 раза дешевле, и там фон `lab` — 52–85 %: P3.2 ускорит и базовые шаблоны.
- `convert("RGB").tobytes()` — 5–14 %, около 5 мс на кадр 1920×1080: заметно для дешёвых сцен.
- Цель этапа 3 «рендер `fake-discounts` быстрее в 2 раза» — **≤ 112 с** на этой машине.
- Цель этапа 4 «`build/` ≤ 40 %» — **≤ 330 МБ**; mix + chapters = 441 МБ из 824 — это P4.1 и P4.2.
