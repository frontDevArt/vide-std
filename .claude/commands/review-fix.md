description: Правки по комментариям ревью — поправить входы и перерендерить только помеченные сцены
argument-hint: "[slug проекта] [--out <выход>]"
---
Проект: $ARGUMENTS

1. `python -m studio review <проект> --list` — открытые комментарии: id, секунда, сцена `chNN/sNN`, время от начала
   сцены, точка кадра (доли ширины×высоты), текст; в конце — строка `Сцены: …`. Нет открытых — сказать и остановиться.
   Если пользователь вставил текст «Скопировать для Claude» со страницы — это тот же список.
2. По каждому комментарию открой `script/<глава>.yaml` и правь **только входы этой сцены** (`lines`, `params`,
   `image:`, шаблон; общее — `project.yaml` лишь с согласия пользователя). Точка кадра подсказывает, о каком элементе
   речь; непонятно — посмотри кадр `python -m studio frame <проект> <секунда>` и спроси, а не угадывай.
   `build/` руками не править. Комментарий про звук или темп — `lines`, а не обрезка речи (CLAUDE.md).
3. `python -m studio validate <проект>`, затем `python -m studio voice <проект>` — **после любой правки сценария**,
   даже только `params`: рендер берёт сцены из `build/timeline.json`, а его пересобирает `voice`. Озвучка из кэша;
   менялся текст `lines` — пересинтез только этих строк (платный голос — сначала смета и «да»).
4. `python -m studio stills <проект> --times <секунды комментариев>` — открой PNG, правка видна?
5. `python -m studio render <проект> --draft --scenes <сцены из п. 1>` (дольше ~5 мин — в фоне). В логе рендера —
   только эти сцены; строка «Устарели и вне --scenes» значит, что правка задела соседей (сдвиг `state`, новый тайминг):
   скажи пользователю, какие, и перерендери их тем же флагом.
6. `python -m studio assemble <проект> --draft`, затем `python -m studio review <проект> --done c1,c2,…` — закрыть
   исправленные. Ответ пользователю: что поменяли по каждому комментарию, какие сцены перерендерены; страница ревью
   (`python -m studio review <проект>`) покажет новую версию — утверждает её клиент кнопкой «Утвердить версию».
